1이 블로그가 굴러가는 구조

[글 작성] ├── (A) https://outvest.kr/admin ← 브라우저만 있으면 됨. 세팅 0 └── (B) src/content/posts/*.md 직접 편집 → git push │ ▼ [GitHub: freerahn6/outvest] ← 콘텐츠의 단일 진실원(SSOT). 별도 DB 없음 │ push 감지 ▼ [Cloudflare Pages] 자동 빌드 1~3분 → https://outvest.kr ▲ [GitHub Actions cron 10분] 예약 시각 지난 글 있으면 Deploy Hook 호출
  • 정적 사이트(Astro)다. 서버도 DB도 없다. 글은 마크다운 파일이고, 발행은 곧 git 커밋이다.
  • 시세 카드는 별도 Cloudflare Worker(kis-proxy)가 한국투자증권 API를 중계하는 구조인데, 현재 꺼져 있다(→ 3장).

2집 PC 최초 세팅 (30분)

2-1. 레포 두 개를 클론한다

레포클론 위치안에 든 것
freerahn6/outvest아무 데나 (회사 PC는 C:\job\analytics)블로그 소스 전부
freerahn6/malgnai-brain~/.claude (경로 고정)에이전트 정의 40개 · knowledge 67개 · 전역 CLAUDE.md

두 번째가 중요하다. an1~an7, 감마 같은 에이전트는 블로그 레포가 아니라 ~/.claude/agents/에 있다. 이걸 안 가져오면 집필·검수 규약이 "an6에게 팩트체크를 맡겨라"라고 해도 an6이 존재하지 않는다.

git clone https://github.com/freerahn6/outvest.git
cd outvest
npm install          # package-lock.json 있으므로 버전 고정 설치됨
npm run dev          # http://localhost:4321

node_modules·dist·.astro는 커밋되지 않는다. 전부 위 명령으로 재생성된다.

2-2. 레포에 없는 것 — 세 가지

없는 것왜 없나없으면 못 하는 일대처
.dev.vars (루트)시크릿이라 gitignore 로컬에서 /admin 띄우기 .dev.vars.example 복사해 값 채우기. 글만 쓸 거면 불필요
KIS 앱키Cloudflare Worker secret에 보관 Worker 재배포·로컬 시세 테스트 README 5장 참고. 지금은 시세 기능 자체가 OFF라 무관
Cloudflare·GitHub 계정 접근당연히 레포 밖 배포·환경변수 변경로그인만 하면 됨

핵심: 글을 쓰고 발행하는 데는 위 세 가지가 하나도 필요 없다. clone + npm install이면 끝이다.

2-3. 필요한 계정 접근 체크리스트

  • GitHub freerahn6 — outvest, malgnai-brain 두 레포 push 권한
  • Cloudflare 대시보드 — Pages 프로젝트 outvest, Worker kis-proxy
  • /admin 비밀번호 (Cloudflare 환경변수 ADMIN_PASSWORD에 설정된 값)

4글 쓰는 세 가지 경로

(A) 브라우저 /admin — 권장. 세팅 불필요

https://outvest.kr/admin → 문장 속 "없습니다"의 '습' 을 클릭 → 비밀번호.

작성·수정·예약·삭제가 되고 저장하면 GitHub에 커밋된다. 자세한 건 docs/관리자-콘솔.md. 집 PC에서 가장 편한 방법이다. 클론조차 필요 없다.

(B) 마크다운 직접 편집 → push

# src/content/posts/새글-슬러그.md 생성
npm run build        # 스키마 오류·빌드 깨짐 확인
git add src/content/posts/새글-슬러그.md
git commit -m "글 발행: 제목"
git push origin main

파일명이 곧 URL이다(새글-슬러그.md → /posts/새글-슬러그/).

(C) 로컬에서 /admin 띄우기 — .dev.vars 필요

npm run build
npm run preview:api      # http://localhost:8788
주의

로컬 admin에서 저장해도 실제 저장소에 커밋된다. 시험할 땐 .dev.vars의 GITHUB_BRANCH를 임시 브랜치로 바꿔라.

5발행 전 필수 — 검수 절차

docs/집필-검수-규약.md를 따른다. 요약하면:

  1. 감마가 주제에 맞는 작성자를 배정하고 검수 강도를 판정한다
  2. 초안은 draft: true로 시작한다
  3. 검수는 작성자가 아닌 다른 에이전트 최소 2명 — 팩트체커 + an7(리스크·면책, 상시)
  4. [치명] 미해결 상태로는 배포하지 않는다
  5. 감마가 판정 → draft: false → 커밋 → push

판별 질문: 이 글에 "틀리면 다음날 정정해야 할 수치·날짜"가 있는가? 있으면 강/표준, 없으면 경량.

이게 형식이 아닌 이유

2026-08-05 「국고채 4%대 시대의 배당주」 집필 시 실제로 걸러진 것들:

  • 초안이 두 달 지난 시장 프레임에 고정 — 7월 코스피 -22%, 한은 금리 인상을 반영하지 못함 (an2가 반려)
  • 절세폭 "49.5%→27.5%"가 한계세율 혼동 — 재계산하니 실제 실익은 배당 1억원 기준 84만원 (an6)
  • "명의 분산" 표현이 증여세·금융실명법 유인으로 읽힘 (an7)
  • 커버 SVG가 다른 글 제목을 하드코딩 출력 (an7)

치명 16건·권고 30건을 거쳐 원고가 두 번 바뀌었다. 검수를 건너뛰었으면 전부 배포 후 정정이었다.

에이전트를 못 쓰는 환경이라면

~/.claude를 클론하지 못한 상태라면, 최소한 규약 §5 체크리스트를 직접 손으로 훑어라. 특히 수치의 기준일, 인용의 원문 취지, 면책 문구 세 가지가 사고의 대부분이다.

4temp/ 정리이전 세션의 검수 리포트 3건이 untracked로 남아 있다. gitignore 추가 / 커밋 / 삭제 중 택일

10절대 하지 말 것

금지
  • 시크릿 커밋 금지. .env, .dev.vars, github_pat_…, KIS 앱키. gitignore에 있지만 -f로 강제 추가하지 말 것
  • 발행된 글의 슬러그(파일명) 변경 금지. 검색엔진에 색인된 링크가 끊긴다. 삭제해도 git 이력에는 남으니 되돌릴 수 있지만, 링크는 못 되돌린다
  • [치명] 지적이 남은 글 발행 금지. 규약 §5
  • 면책 문구 없는 글 발행 금지. 규약 §1-5
  • main에 직접 push가 곧 배포다. 실험은 브랜치에서

이 파일은 docs/에 있어 사이트로 배포되지 않는다(Astro는 public/과 src/pages/만 서빙한다). 운영 정보가 담겨 있으므로 public/으로 옮기지 말 것.
