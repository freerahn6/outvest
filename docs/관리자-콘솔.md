# 관리자 콘솔 — 글관리 · 예약 발행

`/admin` 에서 글을 **작성·수정·예약·삭제**한다. 저장하면 GitHub 저장소에 커밋되고,
Cloudflare Pages 가 그 커밋을 감지해 사이트를 다시 빌드한다.

```
[/admin 화면]
   │ 저장
   ▼
[Pages Functions]  ──GitHub Contents API 커밋──▶ [GitHub: freerahn6/outvest]
   /api/admin/*                                         │ push 감지
                                                        ▼
                                          [Cloudflare Pages 자동 빌드 · 1~3분]
                                                        ▲
[GitHub Actions cron(10분)] ──예약 시각 지난 글이 있으면──┘
     scheduled-publish.yml       Deploy Hook 호출
```

콘텐츠의 단일 진실원(SSOT)은 여전히 **git** 이다. 별도 DB 는 없다.

---

## 1. 최초 1회 설정 (이걸 안 하면 글관리가 안 열린다)

### 1-1. GitHub 토큰 발급
[Settings → Developer settings → Personal access tokens → **Fine-grained tokens**](https://github.com/settings/tokens?type=beta)

| 항목 | 값 |
|---|---|
| Repository access | Only select repositories → **freerahn6/outvest** |
| Repository permissions | **Contents: Read and write** (이것만) |
| Expiration | 1년 권장 (만료되면 글관리가 502 를 낸다 — 갱신 필요) |

발급된 `github_pat_…` 값을 복사한다. **이 값은 한 번만 보인다.**

### 1-2. Cloudflare Pages 환경변수 등록
Cloudflare 대시보드 → Workers & Pages → **outvest** → Settings → **Variables and Secrets**
→ Production 과 Preview **양쪽**에 추가:

| 이름 | 값 | 종류 |
|---|---|---|
| `ADMIN_PASSWORD` | 관리자 비밀번호 (직접 정한다) | **Secret** |
| `SESSION_SECRET` | 아무 긴 랜덤 문자열 32자 이상 | **Secret** |
| `GITHUB_TOKEN` | 1-1 에서 받은 `github_pat_…` | **Secret** |
| `GITHUB_REPO` | `freerahn6/outvest` | Text |
| `GITHUB_BRANCH` | `main` | Text |

> 반드시 **Secret** 으로 넣을 것. Text 로 넣으면 대시보드에서 값이 그대로 보인다.

등록 후 **한 번 재배포**해야 함수가 새 값을 읽는다.

### 1-3. Deploy Hook 생성 (예약 발행용)
같은 화면 → Settings → **Builds** → Deploy hooks → Add
- 이름: `scheduled-publish`
- 브랜치: `main`

생성된 URL(`https://api.cloudflare.com/client/v4/pages/webhooks/deploy_hooks/…`)을 복사.

### 1-4. GitHub Secret 등록
저장소 → Settings → Secrets and variables → Actions → **New repository secret**
- 이름: `CF_DEPLOY_HOOK`
- 값: 1-3 의 URL

## 2. 쓰는 법

`/admin` → 문장 속 **"없**습**니다"의 '습'** 을 클릭 → 비밀번호 입력.

### 글 상태 3가지
상태는 별도 필드가 아니라 `draft` 와 `pubDate` 에서 파생된다.

| 상태 | frontmatter | 사이트에서 |
|---|---|---|
| **게시** | `draft: false` + `pubDate` 가 과거 | 보인다 |
| **예약** | `draft: false` + `pubDate` 가 미래 | 안 보인다. 시각이 되면 자동 게시 |
| **비공개** | `draft: true` | 안 보인다. 시각이 지나도 안 나간다 |

### 반영 시간
| 동작 | 사이트 반영 |
|---|---|
| 저장 / 수정 / 삭제 | 커밋 즉시 빌드 → **1~3분** |
| 예약 발행 | 예약 시각 + **최대 10분** (cron 주기) + 빌드 1~3분 |

### 주의
- **주소(슬러그)를 바꾸면 기존 링크가 끊긴다.** 검색엔진에 색인된 글은 바꾸지 말 것.
- 삭제해도 git 이력에는 남는다 (되돌릴 수 있다).
- 본문은 마크다운이다. 기존 글에 섞인 `<figure>`·SVG 같은 원시 HTML 은 그대로 두면 유지된다.
- 시각은 전부 **한국 시간** 기준으로 입력·표시된다.

## 3. 로컬에서 확인하기

```bash
npm run build          # dist 생성 (Functions 는 dist 를 서빙한다)
npm run preview:api    # http://localhost:8788 — /admin 과 /api/admin/* 둘 다 동작
```

`.dev.vars` 에 로컬용 값을 넣는다 (git 에 안 올라간다):

```
ADMIN_PASSWORD=testpw
SESSION_SECRET=testsecret
GITHUB_TOKEN=github_pat_...
GITHUB_REPO=freerahn6/outvest
GITHUB_BRANCH=main
```

> ⚠️ 로컬에서 저장하면 **실제 저장소에 커밋된다.** 시험할 땐 `GITHUB_BRANCH` 를
> 임시 브랜치로 바꿔 두는 게 안전하다.

예약 스케줄러 단독 실행:
```bash
npm run check:scheduled     # 무엇이 대기 중이고 무엇이 밀렸는지 출력만 한다
```

## 4. 고장났을 때

| 증상 | 원인 · 조치 |
|---|---|
| 글관리에서 "GitHub 토큰이 잘못됐거나…" (502) | PAT 만료·권한 부족. 1-1 로 재발급 후 1-2 재등록 → 재배포 |
| "환경변수 미설정: …" (500) | 1-2 를 안 했거나 재배포를 안 함 |
| 로그인이 자꾸 풀림 | 세션은 12시간. 그 전에 풀리면 `SESSION_SECRET` 이 Production/Preview 에서 다름 |
| 예약 시각이 지났는데 안 나감 | ① Actions 탭에서 `예약 발행 체크` 워크플로가 꺼졌는지 확인 (60일 무커밋 시 자동 중지) ② `CF_DEPLOY_HOOK` 시크릿 확인 |
| "다른 곳에서 이미 수정된 글입니다" (409) | 다른 창·다른 PC 에서 먼저 저장됨. 목록 새로고침 후 다시 편집 |

## 5. 구조 (건드릴 때 참고)

| 파일 | 역할 |
|---|---|
| `src/lib/posts.ts` | **`isLive()` — 공개 판정 단일 출처.** 새 목록·피드를 만들면 반드시 이걸 쓸 것 |
| `src/server/frontmatter.ts` | frontmatter 파싱·직렬화. 모르는 필드도 보존한다 |
| `src/server/github.ts` | GitHub 읽기(GraphQL 1회)·쓰기(REST) |
| `src/server/auth.ts` | HMAC 서명 세션 토큰 (저장소 불필요) |
| `functions/api/admin/*` | Pages Functions 엔드포인트 |
| `scripts/check-scheduled.mjs` | 예약 발행 감시 (사이트맵 대조 방식, 상태 저장 없음) |
| `.github/workflows/scheduled-publish.yml` | 위 스크립트를 10분마다 실행 |
